Articula el cliente web interactivo con el backend en FastAPI, el pipeline de audio (ffmpeg, faster-whisper, Piper TTS), el servidor de inferencia Ollama (Qwen3:4b y embeddinggemma) y las dos áreas de persistencia en PostgreSQL: el esquema transaccional tienda y la base vectorial del agente con extensión pgvector.

Diagrama 2

Diagrama de Secuencia: Consulta por Voz a Acción

Traza cronológica de una interacción hablada típica (ejemplo: "¿Cuántos pedidos van este mes?"). Muestra la captura del flujo de audio en el navegador, la normalización temporal, la transcripción local, el bucle de razonamiento con invocación a herramientas fijas en PostgreSQL, la síntesis del habla con Piper TTS y el retorno simultáneo del audio y los metadatos de trazabilidad. 

sequenceDiagram
    autonumber
    actor Usuario as Comerciante (Voz)
    participant UI as Interfaz Web (Browser)
    participant API as FastAPI Router (/api/voice)
    participant FF as Normalizador ffmpeg
    participant STT as faster-whisper (CUDA)
    participant Agent as app/agent.py
    participant Ollama as Ollama (qwen3:4b-instruct)
    participant Tools as app/tools_demo.py
    participant DB as PostgreSQL (Esquema tienda)
    participant TTS as Piper TTS (es_MX)

    Usuario->>UI: Habla manteniendo pulsado el botón de micrófono
    UI->>API: POST /api/voice (blob audio WebM/Opus)
    Note over API: Inicia medición de latencia global
    API->>FF: Normalizar a WAV 16 kHz mono
    FF-->>API: Archivo WAV temporal
    API->>STT: Transcribir audio (es)
    STT-->>API: Texto: "¿Cuántos pedidos van este mes?"
    
    API->>Agent: chat(text, conversation_id)
    Agent->>Ollama: POST /api/chat (prompt del sistema + historial + mensaje)
    Ollama-->>Agent: Retorna tool_call: metricas_periodo(periodo="mes")
    
    Agent->>Tools: metricas_periodo(periodo="mes")
    Tools->>DB: SELECT count(*), sum(total)... WHERE fecha en mes actual
    DB-->>Tools: 80 pedidos (14 confirmados, 16 nuevos...), $6.078.000 COP
    Tools-->>Agent: JSON con métricas consolidadas del mes
    
    Agent->>Ollama: POST /api/chat (historial + tool_result)
    Ollama-->>Agent: Respuesta final concisa en 3 frases naturales
    
    Agent->>TTS: Sintetizar respuesta audible
    TTS-->>Agent: Archivo audio/uuid.wav generado
    
    Agent-->>API: Respuesta completa + tool_calls + métricas de tiempo (ms)
    API-->>UI: JSON {answer, audioUrl, transcript, toolCalls, timings}
    
    par Reproducción y Renderizado
        UI->>Usuario: Reproduce audio sintetizado en altavoces
        UI->>UI: Despliega mensaje en el chat y actualiza Panel de Trazabilidad
    end
Respaldo de Navegador: Si el sistema no cuenta con Piper TTS disponible o la síntesis falla, el cliente conmuta de forma transparente a la API nativa de síntesis de voz del navegador (speechSynthesis), garantizando continuidad en la experiencia.

Diagrama 4

Diagrama de Flujo: Creación y Confirmación de Pedido (Human-in-the-Loop)

Describe el patrón de control para operaciones críticas con impacto en existencias físicas o compromisos de flete: el copiloto interpreta la orden, valida stock disponible, calcula fletes con transportadoras colombianas y genera una propuesta pendiente en la tarjeta de la interfaz. La transacción solo se materializa en la base de datos si el comerciante pulsa [Confirmar]. 

flowchart TD
    START(["Comerciante: 'Crea un pedido para Laura Gomez en Medellin: 2 tes verdes, contra entrega'"]) --> PARSE["Ollama extrae entidades:
Cliente: Laura Gomez, Destino: Medellin, Items: [Te Verde x2], Pago: contra entrega"]
    
    PARSE --> VALIDATE_STOCK{"Existe stock suficiente
en bodega?"}
    VALIDATE_STOCK -- No --> REJECT_STOCK["Copiloto informa por voz:
'No hay existencias suficientes de Te Verde en bodega.'"]
    REJECT_STOCK --> END_FLOW(["Fin del flujo"])

    VALIDATE_STOCK -- "Si" --> COTIZAR["Consultar tarifas de transportadoras para Medellin:
Calcula flete mas economico y tiempo estimado"]
    COTIZAR --> CALC_TOTAL["Calcular balance financiero:
Subtotal: 48.000 COP + Flete: 12.900 COP = Total: 60.900 COP"]
    
    CALC_TOTAL --> CREATE_PENDING["Insertar en pending_actions (estado='pending'):
Registra ID temporal, datos del cliente, productos y desglose"]
    CREATE_PENDING --> RENDER_CARD["Interfaz Web despliega Tarjeta Pendiente:
• Tabla de productos y cantidades
• Subtotal, Flete y Total en COP
• Botones: [Confirmar] y [Cancelar]"]

    RENDER_CARD --> USER_DECISION{"Decision del

    USER_DECISION -- "Pulsa [Cancelar]" --> CANCEL_ACTION["POST /api/actions/{id}/cancel
• Actualiza pending_actions a 'cancelled'
• Notifica en el chat: 'Accion cancelada. No se modifico la tienda.'"]
    CANCEL_ACTION --> END_FLOW

    USER_DECISION -- "Pulsa [Confirmar]" --> EXEC_CONFIRM["POST /api/actions/{id}/confirm (En modo demo)"]

Garantía Transaccional: La inserción del pedido, la inserción de items, la deducción de existencias en tienda.productos y la bitácora en tienda.acciones se ejecutan dentro de un único bloque transaccional con FOR UPDATE para evitar condiciones de carrera o inconsistencias de stock.
